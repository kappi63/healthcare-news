# スキルの更新手順（最新の精密栄養学・医療情報の取り込み）

このスキルの知識は「生きたナレッジ」として更新していく前提。中核は用語辞書 `references/terms.json`。
以下の原則と手順で、精度と安全性を保ちながらアップデートする。

## 何を更新するか（3つの層）
> **前提（層0・変更不可の運用ルール）**: `references/privacy-handling.md` の仮名化プロトコル。
> 内容の更新・拡張にかかわらず、識別子を持ち込まない／`{{CLIENT_NAME}}` で出力する原則は常に維持する。
1. **`terms.json`（事実の層）** — マーカーの基準値・理想値・高値/低値の意味・関与栄養素・関連マーカー・出典。最も頻繁に更新。
2. **`interpretation.md`（判断の型の層）** — 乖離をどう束ねて物語にするか、改善提案ライブラリ。新しい介入知見はここに。
3. **`ideal-ranges.md` / `report-template.md` / `intake-schema.md`** — 理想値の改訂、文体、問診対応。随時。

## 更新の2モード

### モード1: 手動更新（正本を編集）
- `terms.json` の正本は用語辞書アプリのリポジトリ（GitHub: mhd-apps/precision-nutrition-glossary）。
- 項目の追加・修正はそちらで行い、最新版を `references/terms.json` に同期（差し替え）する。
- 神宮前クリニックが理想値を改訂したら `ideal-ranges.md` と各項目の `optimal` を更新。

### モード2: Claudeによる調査支援つき更新（推奨）
新しいトピックを取り込みたいとき、Claudeに次を依頼する:
1. 「〇〇（例: オメガ3と中性脂肪、ビタミンD新ガイドライン）の最新知見を、信頼できる情報源で調べて」
2. Claudeは reputable な情報源（学会・診療ガイドライン、査読論文、公的機関、一次情報）を検索・精読し、要点と出典を整理。
3. その結果を、`terms.json` の新規/更新エントリ（`optimal`/`high`/`low`/`nutrients`/`related`/`sources` を埋めた形）や `interpretation.md`・`patterns.md` の追記案として**ドラフト**。
4. 人（施術者）が内容を確認してから正本にマージ。

### ★「貼るだけ」更新フロー（不定期運用向け・いちばん手軽）
気づいたときに、手元の資料をそのまま渡すだけで更新できるようにする運用。
1. **渡す**: 論文PDF・書籍の該当ページ・信頼できる記事のURL・メモを、次の一言と一緒に貼る。
   > 「この資料の要点を精密栄養スキルに取り込みたい。追記案を出して。」
2. **Claudeが返す**: 以下をセットでドラフトする。
   - 抽出した要点（自分の言葉で言い換え／原文の丸写しはしない＝著作権配慮）
   - 反映先の具体案（どのファイルのどこに、どう追記/修正するか）
   - `bibliography.md` に追加する出典1行（ID・出典・トピック・根拠タグ）
   - 【確立】か【精密栄養（仮説）】かのタグ付け
3. **承認**: 施術者が「OK」または修正指示。Claudeが確定させ、`bibliography.md` と変更履歴に記録。
4. **回帰確認**: 判定ルール・理想値・パターンを変えた場合は、`precision-nutrition-tests/` の合成サンプルで試走し、既存の所見が崩れていないか確認（下記）。

## 情報源の質のルール（重要）
- 採用してよい情報源: 医学会・栄養学会の診療ガイドライン、査読付き論文（できればレビュー/メタ解析）、公的機関（厚労省・NIH等）、定評ある一次情報。
- `sources` フィールドに必ず出典を残す。出典のない主張は入れない。
- 「確立した知見」と「新しめの仮説（精密栄養学/オーソモレキュラー的解釈）」を区別して記述する。後者は断定せず「〜とする考え方がある」と明示（現状の辞書もこの書き分けをしている）。
- Claudeの学習データは2026年1月時点まで。「最新」を求めるときは必ず検索して現時点の情報を確認し、低品質ソース（まとめサイト等）は避ける。

## 安全と一貫性の担保
- **必ず人がレビューしてからマージ**。医療情報は自動反映しない。
- 「診断ではない／主治医相談」という枠組み（前提条件・注意事項）は変更しない。
- すべての知見追加は `references/bibliography.md` に出典1行を残す（出典なしは入れない）。
- 変更は日付とともに変更履歴に記録する。理想値や判定ルールを変えたら、過去レポートとの整合も意識する。
- **回帰テスト（識別子）**: どの更新でも、テスト実行時に出力へ実名・生年月日等が混入していないかを併せて確認する。
- **回帰テスト**: 判定・理想値・パターンを変えたら、`precision-nutrition-tests/`（架空クライアント3件）で試走し、各ケースの「必ず拾うべき所見」「やってはいけない誤り」が保たれているか確認してから運用に戻す。テストの使い方は同フォルダの README を参照。


## 自動化ポリシー（Claude Codeの日次ニュース連携）
日次のヘルスケアニュース収集ルーティンと連携する場合の原則。**収集・ドラフトは自動、採用は人**。
- **全自動マージは禁止**。ニュースは単発・速報が多く「1本の研究≠確立」。自動追加はサイレントドリフト
  と品質劣化を招くため、必ず人の承認ゲートを通す。
- ルーティンは、精密栄養に関係する候補について**「追加提案」だけ**を生成し、ステージング
  （提案フォルダ or git ブランチ/PR）に置く。正本（terms.json・patterns.md 等）は直接書き換えない。
- 各提案は8項目の理由を付す: 関連性／新規性（重複チェック）／エビデンスの強さ（タグ）／実行可能性／
  反映先（差分案）／安全・医療フラグ／出典1行／回帰テストの対象。
- **理想値（optimal/reference）は日次ニュース由来では変更しない（禁止）**。理想値は神宮前クリニックの
  体系に基づくスキルの土台であり、速報ベースで動かさない。関連ニュースが来ても提案・記録に留め、
  変更は正式な資料の改訂や施術者の明示的な決定があったときにのみ、人の手で行う。
- 出典は reputable のみ（ガイドライン・査読論文・公的機関）。報道は一次情報をたどってから。
- 承認後: 正本へ反映 → `precision-nutrition-tests/` で回帰確認 → bibliography と変更履歴に記録。
- 運用手順書は別添「スキル自動更新エージェント_指示書.md」を参照（Claude Code側に配置）。
