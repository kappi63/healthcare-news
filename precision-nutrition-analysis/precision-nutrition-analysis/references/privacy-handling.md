# 個人識別情報の取り扱い（仮名化プロトコル）

このスキルが扱うデータ（健診結果・血液検査値・問診票）は、日本の個人情報保護法上の
**要配慮個人情報**（病歴・健康診断等の結果）に該当する。氏名と紐づいた状態で外部の
AIサービス上を流れることは、以下の理由で避ける。

- 要配慮個人情報の取得・取扱いには本人の明示的な同意が必要。
- 外国にあるサービスへの提供は「委託だから同意不要」の例外が及ばない（越境移転）。
- 要配慮個人情報が含まれる漏えい等は、**1件でも**個人情報保護委員会への報告と本人通知の対象。
- 氏名等の識別子が付いていなければ、上記のリスクは実務上大きく下がる。

> 法的助言ではない。運用の最終判断は施術者が行う。同意書の整備は別途必要。

---

## 原則（3つ）

1. **識別子はスキルの外に置く** — 氏名・生年月日・住所・連絡先・保険者番号・カルテ番号は、
   解析にも判定にも一切必要ない。必要なのは**年齢・性別・体格**だけ。
2. **症例IDで扱う** — クライアントは `PN-YYYY-NNN` 形式の症例IDで一貫して呼ぶ。
   ID ↔ 氏名の対応表は施術者の手元のみで管理し、会話にもファイルにも出さない。
3. **氏名はプレースホルダで出力する** — レポート内の氏名は `{{CLIENT_NAME}}` のまま出力し、
   実名の差し込みは施術者が手元のWordで行う。

## Step 0 チェック（入力を読む前に必ず実施）

> ### ⚠ 本来のマスクは「Claudeに渡す前」
> Step 0 は**受け取ったあとの出力**を守る仕組みで、送信そのものは止められない。
> 識別子付きのファイルをアップロードした時点で、その情報は既に外部に渡っている。
> **施術者はアップロード前に手元でマスクすること。** Step 0 はその取りこぼしを
> 拾うための二重化であって、代替ではない。

入力ファイルを受け取ったら、**解析に入る前に**識別子の有無を確認する。
識別子が付いたまま渡されていた場合は、次回以降アップロード前のマスクが必要である旨も
併せて伝える。

### マスク対象
| 項目 | 扱い |
|---|---|
| 氏名・カナ・ニックネーム | 削除 →`{{CLIENT_NAME}}` / 症例ID |
| 生年月日 | **年齢（歳）に変換**して以後は年齢のみ使用。日付そのものは保持しない |
| 住所・電話・メール・LINE ID | 削除（解析に不要） |
| 保険者番号・被保険者番号・カルテ番号・検体番号 | 削除 |
| 受診施設名・担当医名 | 削除（季節補正に必要な**採血年月**だけ残す） |
| 顔写真・身分証の画像 | 受け取らない。含まれていたら指摘して除外 |

### 残してよい（解析に必要）
年齢／性別／身長・体重・BMI／採血年月／検査項目名・数値・単位／問診票の回答本文
（回答本文に氏名・勤務先名等が混ざっていたら、その語だけ伏せる）

### 識別子が残っていた場合の対応
1. 解析を進める前に、**どのファイルのどこに何の識別子があるかをユーザーに報告する**。
2. 「このまま進める」「マスク版を送り直す」のどちらかを確認する。
3. 進める場合も、**出力物（レポート本文・ファイル名・中間ファイル）には識別子を一切書かない**。

## 出力側のルール

### レポート本文
- 呼びかけは `{{CLIENT_NAME}}様` と書く。実名は入れない。
- 本文中の二人称は「{{CLIENT_NAME}}様」または「あなた様」で統一。
- 症例IDをレポートに印字しない（施術者の管理台帳側の情報）。

### ファイル名
- 氏名を含めない。`精密栄養解析レポート_PN-2026-047_2026-08.docx` の形式。
- 症例IDも外に出したくない場合は日付のみ（`精密栄養解析レポート_2026-08.docx`）。

### 中間ファイル・作業ディレクトリ
- `/home/claude/` 内の一時ファイル、抽出したCSV/JSON、グラフ画像にも識別子を書かない。
- グラフのタイトル・凡例に氏名を入れない。

### 蓄積しない
- クライアントの個別データを**プロジェクトナレッジやスキル本体に保存しない**。
  セッションスコープで完結させる。知見として残す場合は、必ず匿名の合成ケース
  （`precision-nutrition-tests/` 形式）に書き換えてから残す。

## 出力前チェックリスト（Step 6 に統合）

**まず機械チェックを走らせる:**
```bash
python3 scripts/check_deidentification.py /mnt/user-data/outputs/
```
終了コード0（クリーン）でなければ納品しない。そのうえで以下を目視確認する。

- [ ] レポート本文に実名・生年月日・住所・連絡先・番号類が**1つも**含まれていない
- [ ] 呼びかけが `{{CLIENT_NAME}}様` のプレースホルダになっている
- [ ] ファイル名に氏名が含まれていない
- [ ] 埋め込んだグラフ・表に識別子が写り込んでいない
- [ ] 施術者への引き渡しメッセージで、実名差し込みが手元作業である旨を伝えている

## 関連する運用（スキル外・施術者の責任範囲）

このスキル側の仮名化だけでは足りない部分。問診票・契約側で整備する。

- **同意取得**: 要配慮個人情報の取得目的／AI解析の利用と海外サーバでの処理（移転先国・
  その国の保護制度・移転先の措置）／保存期間と削除方法／第三者提供の有無を明記した同意条項。
- **対応表の管理**: ID ↔ 氏名の対応表はオフラインまたは施術者管理下のみ。バックアップも同様。
- **契約プランの確認**: 利用中のAIサービスのデータ保持期間・学習利用の扱いを確認し、
  該当ポリシーを保存して同意書の根拠資料にする。
- **削除運用**: 解析完了後、アップロードした原本と中間ファイルの削除手順を決めておく。
