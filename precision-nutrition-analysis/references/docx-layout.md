# DOCX レイアウト（日本語Word特有の落とし穴）

公開スキル `/mnt/skills/public/docx/SKILL.md` は .docx の作り方全般を扱うが、
**日本語文書に固有のレイアウト崩れ**は範囲外。ここは毎回同じ場所でつまずくので、
対処を運用知識として固定しておく。

対象は Node の `docx` ライブラリ（`Packer.toBuffer()` パターン）で生成する前提。

---

## 1. 行グリッド（docGrid）— 行間が勝手に広がる

### 何が起きるか
日本語の Word 文書は、既定で**セクションに「行グリッド」が敷かれている**（`sectPr` の
`<w:docGrid w:type="lines" w:linePitch="..."/>`）。段落はこのグリッドに吸着するため、
行間を 1.15 と指定しても**グリッド1行分に切り上げられる**。結果：

- 指定した行間が効かない／想定より広い
- 見出しや表の直後が不自然に空く
- 1ページに収めたはずの内容が2ページに割れる
- LibreOffice でPDF化したときとWordで開いたときで見え方が違う

### 対処（生成時）
段落プロパティで `snapToGrid` を切る。**全段落に付ける**のが確実。

```js
new Paragraph({
  children: [ new TextRun("…") ],
  // ↓ これ。付け忘れた段落だけがグリッドに吸着してズレる
  snapToGrid: false,
})
```

見出し・表内の段落・リストにも同じく必要。`docx` ライブラリのスタイル定義側で
既定にしておくと付け忘れが減る。

### 対処（生成後・後処理）
付け忘れた場合や、既存の .docx を直す場合は後処理スクリプトを使う。

```bash
python3 scripts/fix_grid.py 出力.docx --check          # まず診断
python3 scripts/fix_grid.py 出力.docx                  # styles.xml の既定に snapToGrid=0
python3 scripts/fix_grid.py 出力.docx --docgrid-off    # 直らなければグリッド自体を無効化
```

`styles.xml` の `docDefaults` に入れるので、**1箇所で全段落に効く**。
段落ごとに付けるより後処理としては確実。

## 2. 游ゴシック（Yu Gothic）— 行がはみ出す

### 何が起きるか
游ゴシックは**行高（line height）が他の和文フォントより大きい**。
`lineRule: "auto"`（フォントに対する倍率指定）のままだと、指定した行間より実際が広くなり、
ページ末で1行あふれる・表のセル内で文字が切れる、といった崩れが出る。

### 対処
**行間を固定値（`exact`）で指定する。**

```js
new Paragraph({
  spacing: {
    line: 300,            // twips（20 twips = 1pt）→ 300 = 15pt
    lineRule: "exact",    // ★ auto ではなく exact
  },
  snapToGrid: false,
})
```

**目安**：本文 10.5pt なら `line: 300`（15pt）前後。詰めすぎると
ルビ・上付き・大きめの記号が切れるので、**フォントサイズの 1.4〜1.6 倍**を下限にする。

### ⚠️ 後処理で一括変換しない
`auto` → `exact` の機械的な置換は**やってはいけない**。適切な固定値は段落ごと
（本文・見出し・表・脚注）で違い、一律に当てると今度は文字が切れる。
`fix_grid.py` は `lineRule="auto"` を**検出して報告するだけ**で、書き換えない。

## 3. 表のはみ出し

- 列幅は `WidthType.DXA`（twips）で**絶対値指定**する。`AUTO` は日本語で意図どおりに割れない。
- A4 縦・標準余白なら、本文幅はおよそ **9,000 twips**。列幅の合計をこれに収める。
- セル内の段落にも `snapToGrid: false` が要る（表の中だけ行間が広がる原因になる）。
- 長い検査項目名は折り返す前提で、**数値列を固定幅・項目名列を可変**にすると崩れにくい。

## 4. 生成後の確認手順（毎回）

見た目の崩れは目視でしか分からない。**納品前に必ずPDF化して見る。**

```bash
# 1. PDF に変換
soffice --headless --convert-to pdf --outdir /mnt/user-data/outputs 出力.docx

# 2. ページ画像にして目視
pdftoppm -png -r 150 出力.pdf page
```

見るポイント：

- [ ] 行間が均一か（グリッド吸着が残っていると段落ごとにばらつく）
- [ ] ページ末で不自然に切れていないか
- [ ] 表が右にはみ出していないか。セル内で文字が切れていないか
- [ ] 見出しと本文の間隔が意図どおりか
- [ ] グラフ画像が枠内に収まっているか

> **LibreOffice の見え方 ≠ Word の見え方。** フォント置換が起きるため、
> 完全な一致は期待しない。ここで見るのは「破綻していないか」であって、
> 最終的な体裁は施術者が Word で開いて確認する。

`privacy-handling.md` の引き渡し文とあわせて、次を添える。

> Word で開いたときにフォントが置き換わると、行間や改ページの位置が変わることがあります。
> 游ゴシックが入っていない環境で開く場合はご注意ください。

---

## トラブル対応の順序

1. `fix_grid.py --check` で診断する（原因の切り分けが先）
2. `snapToGrid` が原因 → `fix_grid.py` で修正
3. 直らない → `--docgrid-off` でセクションのグリッドを無効化
4. それでも行があふれる → **游ゴシックの行高**。生成側で `lineRule: "exact"` に変える
5. 表だけ崩れる → 列幅を DXA の絶対値にする／セル内段落の `snapToGrid`
6. 毎回 PDF 化して目視。**直したつもりで終わらせない**
